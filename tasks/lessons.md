# Lessons

## 2026-08-13 — Technical coherence is not product novelty

- A concept can pass dual-track removal tests and still be a familiar authorization pattern with new infrastructure underneath.
- Before recommending a finalist, compare its core user-visible mechanic against general Web3 primitives, not only the event's 99-signal competitor corpus.
- Expiring permissions, one-use allowances, session keys, capability tokens, and recurring-payment controls must be treated as prior art for Mandate Zero.
- Score “protocol composition novelty” separately from “product/mechanism novelty”; judges experience the latter first.
- If the plain-language description sounds like an existing control (“turn off auto-debit”), reopen ideation instead of defending architectural depth.

## 2026-08-13 — Broad prior art belongs in a post-freeze hard gate

- Preserve generator independence: do not expose named standards, products, competitors, mechanism kill lists, or differentiation prompts before raw ideas are durably frozen.
- Build a gate-only Global Mechanism Prior-Art Registry from primary standards, wallet/account modules, established DeFi patterns, and shipped products before evaluating the frozen pool.
- Apply a plain-language substitution test after the freeze. If an idea becomes a familiar mechanism with “Flare/FCC/FAssets” substituted in, kill it unless a new load-bearing state transition or user outcome remains.
- Require separate hard scores for user-visible mechanism novelty, Flare composition novelty, demo surprise, and exact-action feasibility. High infrastructure depth cannot compensate for low mechanism novelty.
- A surviving asset action must cite an official callable interface, supported network, and judge-visible receipt. Protocol-level prose without a public builder path is not buildability.

## 2026-08-13 — A no-finalist checkpoint is not project termination

- When the user says not to launch the next round automatically, close the current round and pause; do not frame that pause as ending Warroom.
- Preserve the distinction between a round boundary and a terminal decision. Only the user can end the search.
- This project numbers Warroom attempts as rounds. After Round 6, the next continuation is Round 7, not an ambiguous v2/v3 label.

## 2026-08-13 — V4 restores dual-track targeting without restoring decorative FCC

- Dami requires every V4 finalist to incorporate both Interoperable Asset Products and Confidential Compute Apps.
- The V3 single-track pivot remains diagnostic evidence: forced FCC previously created artificial buyers, datasets, and workflows.
- Reconcile both facts by searching only observed workflows where confidential computation is naturally necessary and causally controls a real interoperable asset transition.
- Require separate removal tests plus one joined proof path; two features or invented private input do not satisfy the correction.

## 2026-08-13 — Correct version history from preserved evidence

- The Flare artifacts do not contain an explicit Warroom V3 launch; they use Round 1, Round 2, and Round 3.
- Round 2 was rejected because Exit Relay and Forget-to-Redeem invented their buyers, workflows, private inputs, economic roles, and authority paths—not because dual-track targeting itself was invalid.
- Round 3 was the market-reality repair: dual-track generation continued, but every product needed primary demand evidence and complete end-to-end operability.
- The later single-track pivot followed 0/40 survivors across Rounds 3–4 and is a separate event; do not conflate it with the Round 2 rejection.
