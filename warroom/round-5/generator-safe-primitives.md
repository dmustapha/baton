# Round 5 Generator-Safe Primitive Deck

Track: **Interoperable Asset Products only**

These are mechanism ingredients, not product templates.

## Primary primitives

### Cross-chain lifecycle state machine

Treat XRP payment, proof, FXRP state, downstream use, recovery, and redemption as explicit states with controlled transitions and receipts.

### Irreversible-action preflight

Resolve current addresses, minimums, fees, tags, recipients, limits, and expected outcomes immediately before the user signs an external payment.

### Native exception completion

Detect an exact failure state, expose only protocol-supported actions, execute the user's chosen recovery/default/retry path, and reconcile final ownership.

### Self-authorized asset composition

Let the holder acquire FXRP and perform a meaningful application action under the same clearly bounded authorization, with a credible exit.

### Proof-carrying receipt

Bundle source transaction, protocol proof/event, asset transition, current owner, and failure/recovery status into a replayable receipt.

### Negative-evidence action

Use a supported proof of nonexistence or deadline state to trigger an exact native default, claim, or safe refusal.

### Participant economics

Make an existing fee, premium, collateral cost, reward, or capital-efficiency improvement the product's measurable outcome.

### Versioned integration route

Bind tags, memos, recipients, executors, network, and contract addresses to an explicit version with safe migration and reconciliation.

### Bounded batch execution

Aggregate actions only when every member has the same authorized actor, exact interface, deterministic failure handling, and individual receipt.

### Before-and-after solvency or ownership proof

Show who owns what, which obligation changed, and which collateral or balance remains before and after the action.

## Cross-pollination primitives

- Forced expiry and reauthorization.
- Reversible staging before irreversible completion.
- Live performance receipts instead of projected benefit.
- First-session countdown/reveal/consequence.
- Closed-loop diagnosis → action → verification.
- Portable proof bundles for support and audit.
- Progressive disclosure: ordinary user first, raw protocol evidence on demand.

## Winning constraints

1. The asset lifecycle is the product, not decoration.
2. The buyer already performs the workflow and controls the action.
3. The mechanism remains interesting after all Flare names are replaced with generic nouns.
4. The demo shows real value/state movement and a failure safeguard in under three minutes.
5. A documented native feature is an ingredient, not automatically an invention.

## Anti-patterns

- Generic dashboards, alerts, or transaction explorers.
- Arbitrary FXRP transfers presented as interoperability.
- Project-funded fixtures presented as market demand.
- Wrappers around native recovery with no new outcome.
- Fictional agents, providers, treasuries, exchanges, or budgets.
- Unsupported PMW, protocol-capacity, routing, exchange-credit, or custodian authority.
- Generic escrow, payments, payroll, lending, or portfolio automation without a new mechanism.
